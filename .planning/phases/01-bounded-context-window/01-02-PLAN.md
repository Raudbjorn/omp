# Plan 01-02: Observability Wiring and Bounding Logic

<objective>
Wire structured logging for per-turn inclusion/exclusion decisions and token telemetry. Implement the core bounding logic: hard message cap via recentMessageCap, aggressive tool transcript exclusion beyond the cap, and lightweight markers for excluded turns. This is the heart of context bounding.
</objective>

<must_haves>
- logger.debug called with per-turn TurnDecision[] after every transformMessages() call (OBSV-01)
- logger.debug called with token counts before/after bounding (OBSV-02)
- transformMessages() uses recentMessageCap as absolute token cap instead of percentage-derived budget (BOUND-01)
- Tool call/result pairs beyond recentMessageCap are excluded entirely, not just stubbed (BOUND-02)
- Excluded turns are replaced with a lightweight marker message so the model knows content was omitted (BOUND-03)
- In a 50+ turn session, token telemetry shows a ceiling near the configured cap
</must_haves>

<task id="2" title="Implement token-based bounding in transformMessages()">
<read_first>
- packages/coding-agent/src/context/assembler/message-transform.ts (transformMessages at ~line 440, segmentIntoTurns, computeBudgetDropCount, stubToolResults, TurnDecision, TurnDecisionAction)
</read_first>
<action>
In `message-transform.ts`, modify `transformMessages()`:

1. **Replace turn-count hot window with token-based cap:**
   - Current logic: keep last `hotWindowTurns` turns verbatim, stub tool results in older turns, drop oldest if over budget
   - New logic: walk turns from newest to oldest, accumulating token count. While under `recentMessageCap`, keep turns verbatim. Once `recentMessageCap` is reached, all remaining older turns are excluded.

2. **Enhance tool transcript exclusion (BOUND-02):**
   - Current: older turns get tool_result content stubbed (replaced with compact pointer)
   - New: turns beyond `recentMessageCap` are excluded entirely (not kept, not stubbed). Tool call/result pairs beyond the cap vanish from the active window.
   - Within the cap, keep existing stubbing behavior for tool results in non-recent turns (the boundary between "recent" and "stubbable" can be the same as the cap, or a fraction of it)

3. **Add exclusion markers (BOUND-03):**
   - When turns are excluded (dropped), inject a single lightweight synthetic message at the exclusion boundary
   - Marker format: `[Turns {first}-{last} excluded: {count} turns, ~{tokens}K tokens. Use read/grep/recall to recover specific content.]`
   - The marker is a user-role text message inserted where the excluded turns were
   - Only one marker per contiguous exclusion block (don't create one per dropped turn)

4. **Update TurnDecision reasons:**
   - Keep existing reasons: `"hot-window"`, `"no-tool-results"`, `"beyond-hot-window"`, `"budget-exceeded"`
   - Add new reason: `"beyond-message-cap"` for turns excluded by recentMessageCap
   - Use `"kept"` action for turns within cap, `"dropped"` for turns beyond cap
   - TurnDecisionAction values stay: `"kept" | "stubbed" | "dropped"` (existing enum)
</action>
<acceptance_criteria>
- `message-transform.ts` contains `"beyond-message-cap"` as a TurnDecision reason
- `message-transform.ts` contains exclusion marker text matching `excluded:` and `recover`
- `transformMessages` function uses `recentMessageCap` for bounding (not `hotWindowTurns`)
- Bun type check passes: `bun check` exits 0
</acceptance_criteria>
</task>
